# v15 — лагающий скролл в «Подписке» (Bedolaga cabinet Mini App)

## Что тормозит

На маршруте `/subscription` постоянно крутятся **две** CSS-анимации, которые
нельзя вынести на композитор, поэтому браузер перерисовывает их **каждый кадр**
и заново растеризует тайлы прокрутки под ними. Пока палец тянет страницу, это
и есть тот самый рывками идущий скролл.

1. **`.hover-border-gradient`** — вращающаяся рамка. Анимируется
   `--border-angle`, зарегистрированное через `@property` кастомное свойство,
   которое подставляется в `conic-gradient`. Анимации registered custom
   properties Chromium композитить не умеет: каждый кадр — полная перерисовка
   фона элемента. На «Подписке» таких элемента два одновременно: карточка
   «Подключить устройство» (`Subscription.tsx`) и CTA продления
   (`PurchaseCTAButton.tsx`). На Дашборде — один (`SubscriptionCardActive.tsx`),
   поэтому там заметно меньше.

2. **`.animate-unlimited-flow`** — полоса безлимитного трафика анимирует
   `background-position`. Тоже paint-only и тоже `infinite`.

Отдельно, но помельче: кулдауны обновления трафика (30 с) и перевыпуска
(15 мин) хранились как убывающие счётчики в самом компоненте страницы, из-за
чего весь маршрут на 2100 строк перерисовывался раз в секунду всё это время.
Каждый такой коммит React, попавший в момент скролла, съедает кадр.

## Замеры

`measure.mjs` гоняет синтетический тач-скролл по разметке «Подписки» с
дросселем CPU 6× и считает работу main-thread по трассировке DevTools.
6 секунд скролла:

| метрика                  | сейчас  | с фиксом |
| ------------------------ | ------- | -------- |
| main-thread render work  | 2100 ms | 30 ms    |
| Paint                    | 330 ms  | 0 ms     |
| RasterTask               | 1250 ms | 0.2 ms   |
| Style recalc             | 380 ms  | 10 ms    |

То есть две декоративные рамки занимали ~35 % одного ядра непрерывно — ровно
поэтому в Telegram WebView проседал не только скролл, но и весь телефон.

## Что делает фикс

На тач-устройствах и экранах уже 1024px угол градиента фиксируется, анимация
выключается. Рамка остаётся ровно такой, какой она выглядит в любом отдельно
взятом кадре вращения — акцентный «блик» на месте, цена за кадр нулевая.
На десктопе вращение сохраняется. Ровно такой же размен кабинет уже делает
для `backdrop-filter` ниже 1024px (`globals.css`, «MOBILE PERFORMANCE»).

## Как применить

### Быстро, на живом сервере (только CSS, без пересборки)

```bash
python3 deploy_v15_scroll_fix.py              # применить
python3 deploy_v15_scroll_fix.py --dry-run    # посмотреть, что изменится
python3 deploy_v15_scroll_fix.py --revert     # откатить
python3 deploy_v15_scroll_fix.py --root /path/to/cabinet
```

Скрипт трогает **только `index.html`** и только добавляет один `<style>` перед
`</head>`. Ни один JS-чанк не переписывается, каталоги `/assets/vN/` не
плодятся, хешированные имена файлов не предполагаются. Это сделано намеренно:
все прошлые попытки (v4…v14) правили минифицированные чанки по точным
строковым «иголкам» — отсюда и чёрные экраны, и откаты. Блок стилей после
бандла сломать загрузку модулей не может, худший исход здесь — «ничего не
изменилось», а не пустое мини-приложение.

`index.html` отдаётся с `no-cache`, так что после применения достаточно
полностью закрыть мини-приложение (смахнуть, а не «Назад») и открыть заново.

Если кабинет в Docker:

```bash
docker cp <container>:/usr/share/nginx/html/index.html /tmp/index.html
python3 deploy_v15_scroll_fix.py --root /tmp
docker cp /tmp/index.html <container>:/usr/share/nginx/html/index.html
```

### Правильно, в исходниках (нужна пересборка)

`0001-subscription-scroll.patch` — патч к
[BEDOLAGA-DEV/bedolaga-cabinet](https://github.com/BEDOLAGA-DEV/bedolaga-cabinet)
(база: `0c1510f`, v1.64.0). Помимо CSS он чинит посекундные перерисовки
маршрута, чего из `index.html` сделать нельзя.

```bash
git apply /path/to/0001-subscription-scroll.patch
npm run build
```

Проверено на v1.64.0: `tsc --noEmit` чистый, `biome check` не добавляет ни
одного нового замечания, `vite build` проходит.

## Файлы

| файл                          | что это                                                     |
| ----------------------------- | ----------------------------------------------------------- |
| `deploy_v15_scroll_fix.py`    | применение/откат на живом сервере, только `index.html`       |
| `subscription-scroll-fix.css` | тот же CSS отдельным файлом, если удобнее подключить руками  |
| `0001-subscription-scroll.patch` | патч к исходникам кабинета (CSS + перерисовки React)      |
| `bench.html`                  | разметка «Подписки» с дословно скопированным CSS из кабинета |
| `measure.mjs`                 | замер работы main-thread во время скролла, до/после          |
| `verify.mjs`                  | проверяет, что инъекция реально победила в каскаде           |

Для `measure.mjs` / `verify.mjs` нужны Chrome и `npm i puppeteer-core`.

```bash
node measure.mjs                 # 6s скролла, до/после
node verify.mjs /srv/cabinet     # проверка уже применённого фикса
```

`verify.mjs` пропускает десктопные проверки, если окружение сообщает
`hover: none` — headless Chrome и голый Xvfb/VNC не отдают наличие указателя,
так что эту половину медиа-запроса там не проверить.
